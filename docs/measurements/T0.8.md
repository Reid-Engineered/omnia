## Protocol

Use release `scene-counts`, unchanged pin, full-screen native viewport: 1920×1080 logical
at 100%; S1 only at 1536×864 logical at 125%. Ten interleaved repetitions per case,
rotating case order per pass, 600 measured frames per run and 60 warmup frames.
The script sets OMNIA_BENCH_FULLSCREEN=1 (verified against
`gpui/src/platform.rs:2802–2810`) and rejects wrong adapters or viewport/scale values.
`crates/omnia-bench/src/spike/measure-ref.sh` copies the PowerShell case list (including
baseline and 25k/70k quads-only), recording AC online, all CPU governors and available
power profile immediately before and after each run in `runs.jsonl`. No sweeps requested.
S2 is outside the requested run list. T0.6 and the owner retain the rendering decision.

The font image test in omnia-app is cfg-gated on Linux/FreeBSD because it requires
G12 readback. Its image assertions remain intact on the supported platforms.
Atlas payload estimates use the verified wgpu rule (`gpui_wgpu/src/wgpu_atlas.rs:188–201`),
matching DirectX's 1024 minimum and R8 monochrome format; the fixed runs do not establish
the second-sweep cap or rotated image quality.

## Display bring-up

The first 600-frame campaign baseline and a direct reproduction timed out at the
unchanged 126-second watchdog, before producing JSON. The session was unlocked,
but `kscreen-doctor --dpms show` established that eDP-1 was off. KWin reported
an active window with stale non-fullscreen geometry. Waking the panel with
`kscreen-doctor --dpms on` and holding a temporary KDE inhibitor let the next
600-frame diagnostic complete with fullscreen=true and correct dimensions.
No claim of a GPUI frame-loop defect follows from the sleeping-panel failures.
Failed logs and power records remain under `T0.8/failures/`.

Campaign command (no compilation during timed runs):

```sh
kde-inhibit --power --screenSaver crates/omnia-bench/src/spike/measure-ref.sh campaign docs/measurements/T0.8 1920x1080 10
```

The inhibitor lasts only for this command; no idle timeout, governor, power
profile or other persistent system setting was changed. The harness leaves
fullscreen geometry to the Wayland compositor instead of issuing a competing
resize immediately after opening. Every result now reports fullscreen, and
the script checks it. DPMS state is included in power snapshots.

The legacy spike config field `reference_machine=false` is a hardcoded T0.4
metadata field, not hardware detection. Qualification here uses recorded device,
viewport, scale, power and the reference protocol, independently of that field.

An additional S1 quads-only load is interleaved with the remaining 100% scenes:
18,999 wire quads plus the paper quad, exactly 19,000 primitives, for T-present.
The PowerShell case list is retained in full. This avoids extrapolating latency
from the 16,485- or 25,185-primitive wire-and-grid cases at the native viewport.
This is the spike's all-quad load, not a future mixed document scene.

## Outcome-table condition, not a decision

The measurements match the condition **“T-quad fails at 25k”**, whose row in
plan section 8 is labelled **Plan C**. Text and replay also miss their limits.
This records the numerical conditions; it does not select or approve a rendering
plan. The row's Direct3D 11 implementation wording is Windows-specific (G11),
while this reference machine uses Vulkan. **T0.6 and the owner decide.** D4,
thresholds, budgets, the GPUI revision and subsequent rendering tasks are unchanged.

The T-present pass is for the 100% all-quad spike and GPUI's CPU submission metric;
it does not establish mixed-document input-to-scanout latency or the 125% exact-19k
case. Rotated/mirrored image quality, second-sweep atlas growth, Linux real-input S7,
and S2 were outside the requested runs. Linux image readback is unsupported, not a
successful golden or a GPU-free capture result.
