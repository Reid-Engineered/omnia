# W1.3: snap rules (WD5)

Measured 2026-11-16 on a Windows development machine, **not the reference machine**.
WB5 (`snap` p99 < 0.2 ms on the 10,000-part sheet) is pending on the Orion reference
machine under canvas plan section 2.1. These numbers certify nothing.

- CPU: Intel Core i7-14650HX. RAM: 31.6 GB.
- GPU: NVIDIA GeForce RTX 5060 Laptop GPU and Intel UHD Graphics (unused: the command is
  CPU-only and opens no window).
- OS: Windows 11 Home 10.0.26200. Display: 1920 x 1200 at 165 Hz; scale factor not
  measured (no window).
- Power: on AC (battery status 2); Windows power scheme "Silent". Governor and background
  load not controlled.
- Rust 1.98.1, release profile. Binary built from branch `task/W1.3-snap-rules` after the
  "radius wins" change and the merge of `main` at 1f9b6de.
- The workload models 100% zoom (K3: 20 px per 2.54 mm grid step), so WK4/K14's 10 px
  snap radius is 1,270,000 nm; the grid is 2,540,000 nm (K2).

These are single diagnostic runs, not a section 2.1 campaign (no ten interleaved
repetitions), so they are evidence only.

## Protocol

```powershell
cargo build --release -p omnia-bench
./target/release/omnia-bench.exe hit --sheet 10k --snap --json docs/measurements/W1.3/hit-10k-snap.json
./target/release/omnia-bench.exe hit --sheet dense --snap --json docs/measurements/W1.3/hit-dense-snap.json
```

T2.4's generator, seed 42, unchanged. Probes are deterministic, in item id order:
a third of the radius off every pin (aim: pin); empty space between parts (grid); past
each wire end along the wire, half the radius out (wire end); diagonally off each far end
(wire end or junction); a quarter and nine tenths of the radius aside of each wire's
middle (wire body). Every probe is snapped once in warmup, outside timing, which also
gives `probe_classes`. 20,000 individually timed snaps then step through the probes with
a stride coprime to their count (`classes`). Percentiles are nearest rank, in ms.

`unreachable_classes` is computed from the sheet alone: `junction` needs a point where
three or more wire ends meet without a pin; `wire_body` needs a grid point strictly
inside a wire (a body target at an end loses to that end).

### Classes the gate sheet cannot produce

On `10k` every wire is a half-grid stub leaving a part's first pin, so:

- **Junction**: the only points with more than one wire end are pins (two ends each),
  and a pin outranks the end class at the same point. No cursor position can give a
  junction.
- **Wire body**: a half-grid stub's only grid point is one of its ends, so a body target
  is always an end, which is then in the radius and wins. No cursor position can give a
  wire body.

The generator was not changed. The closest legitimate probes are kept: the probes nine
tenths of the radius aside of each wire's middle scan every class (pins, ends, bodies)
before falling back to the grid, which is the longest path through `snap`. `dense`
reaches the junction class (424 timed); no generated sheet reaches the wire-body class
at the default grid. The unit tests cover both classes directly.
`snap_report_on_10k_measures_every_reachable_class` requires every class to be non-zero
on `10k`, both over all probes and in the timed samples, unless `unreachable_classes`
excuses it; `unreachable_classes_tracks_sheet_structure` checks that a sheet able to
produce them is not excused.
