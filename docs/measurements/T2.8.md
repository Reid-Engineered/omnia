# T2.8: Doc integration

Measured 2026-11-16 on the Windows development machine, not the Q4 reference machine.
Status: needs-human. Functional acceptance passes; the 1 ms edit budget is not certified.
The 20k-wire split has observed >1 ms tails. No threshold, range or check was relaxed.

## Hardware and protocol

ASUS TUF Gaming F16, Intel Core i7-14650HX; NVIDIA RTX 5060 Laptop GPU and Intel UHD
Graphics; Windows 11 Home; Rust 1.98.1. Active adapters reported 1920 x 1080 at 60 Hz
and 1920 x 1200 at 165 Hz. Per-monitor scale was not measured. These CPU-only benches
open no window and do no GPU work; viewport queries model 100% zoom (20 px/grid step).
Windows power scheme: Silent. Background load, power source and thermals were uncontrolled.
These observations cannot certify a Linux Orion reference budget.

Commands (release, Criterion 0.8, system allocator):

```powershell
cargo bench -p omnia-bench --bench index --bench connectivity
cargo bench -p omnia-bench --bench connectivity
```

Both harnesses now live in omnia-bench, so omnia-doc has no dev dependency on a crate
that depends on it. No new packages or licences: Criterion moved between dev-dependency
lists. The real T2.4 Parts10k generator (seed 42, exactly 10,000 parts and 20,000 wires)
supplies stored art bounds and pins. The previous synthetic doc benches are removed.
Historical missing-generator comments in T2.2/T4.1 describe their original runs; this
measurement supersedes those workload caveats.

Setup/rebuild and cleanup are excluded from edit timing. Add and remove are separately
timed, restoring the same topology between iterations. Criterion uses 20 samples, 1 s
warmup and a 2 s target (automatically extended where needed). Its intervals below are
estimates of mean time, not per-edit tail guarantees. Raw outputs are in
[T2.8-initial.txt](T2.8-initial.txt) and [T2.8-connectivity.txt](T2.8-connectivity.txt).
The first run overlapped workspace compilation/tests; the second followed those builds.
Criterion's automatic comparisons between these runs are not controlled regressions.

## Observations

Initial run mean estimates (low / estimate / high):

- Real 10k leaf add: 39.659 / 43.782 / 47.002 ns; remove: 77.836 / 92.257 / 104.33 ns.
- Real 10k connectivity rebuild including pins: 35.982 / 37.967 / 40.163 ms.
- 5k GND/VCC bridge add: 5.052 / 5.422 / 5.938 us; remove: 127.73 / 137.42 / 151.35 us.
- 20k chain middle add: 56.118 / 57.378 / 58.789 us; remove: 704.82 / 719.88 / 736.56 us.
- Doc 4K query: 4.1433 / 4.2435 / 4.3722 us.
- Whole-sheet query: 152.61 / 156.89 / 161.03 us.
- Real 10k generation including owned derived state and destruction:
  17.447 / 18.389 / 19.610 ms (still far below T2.4's 2 s criterion here).

Second run mean estimates:

- Real 10k leaf add 35.504 ns, remove 48.878 ns; rebuild 8.9764 ms.
- Label-heavy bridge add 3.722 us, remove 99.536 us.
- 20k chain middle add 58.573 us, remove 805.36 us (interval 774.41--851.75 us).

The label case has 5,000 separate one-wire geometric components, alternating GND/VCC.
Adding a bridge shorts both logical nets; removing it forces a logical re-flood through
all 5,000 components. The chain case contains 20,000 wires; removing its middle segment
forces a geometric re-flood into two large components.

To expose tails hidden by Criterion means, the second harness also reports 1,000
individual add/remove pairs for each workload, including timer/black-box overhead:

- Real 10k leaf: add p99 0.000100 ms, max 0.000600 ms; remove p99 0.000100 ms,
  max 0.001700 ms; zero >=1 ms observations for either operation.
- Label-heavy bridge: add p99 0.004700 ms, max 0.022600 ms; remove p99 0.116800 ms,
  max 0.155500 ms; zero >=1 ms observations for either operation.
- 20k middle: add p99 0.130000 ms, max 0.387600 ms, zero >=1 ms observations;
  remove p99 1.082600 ms, max 1.478400 ms, **25/1,000 >=1 ms observations**.

The large split misses the 1 ms budget in individual observations despite a sub-ms mean.
This is not a passing performance claim. Reference-machine timing, and optimization if
it reproduces there, remain before marking the task done. Rebuild/generation are not
single-edit operations and are not compared to the 1 ms edit budget.

## Correctness and compatibility

Doc maintains SpatialIndex, incidence and Connectivity for all crate-private insert,
remove and restore methods. Bulk construction and loading use these same validated
paths, including reserved IDs. Inserts never recycle arena IDs; restore only fills an
allocated empty slot. Connectivity independently supports replacing live IDs.
Part body bounds are transformed and clamped at sheet edges; indexing unions that body
with world pins. Hit testing uses the body, snapping sees pins. Callers provide local
bounds/pins; omnia-doc remains independent of omnia-symbols and GPUI.

RON v2 embeds local art bounds as well as pins; v1 is explicitly rejected rather than
guessing geometry. Save/load equality still includes reserved slots, geometry and revision,
excluding derived caches. This constructor/format change is intentional and documented
in plan section 9. NetIds are handles valid only until the next edit.

Validation: cargo fmt --all --check; cargo clippy --workspace --all-targets -- -D warnings;
cargo test --workspace; cargo deny check; git diff --check. All pass. Workspace tests
include 38 doc unit/property tests and two allocation tests; the pre-existing ignored
manual generator timing test is covered by the release generation benchmark above.
INV10 checks full geometric and logical point partitions, net membership/labels and
internal reciprocal indices/counts/free slots after each edit. Randomized sequences
cover pins, standalone label-only components, live connectivity ID replacement, and
legal Doc remove/restore for every kind, with a save/load and query oracle at every step.
INV1 still rejects zero-length wires; INV3 and INV9 and the sheet-edge regression remain.
The Doc query counting-allocator test asserts zero allocations with capacity.

Two overlapping workspace test invocations encountered Windows executable file locks
(LNK1104 / OS error 32); rerunning the full suite serially passed. Cargo deny reports
existing dependency warnings only. No rendering work or T2.5 gate bypass is included.

T2.4's heading was corrected from doing to done: PR #19 is merged (2026-11-16), its log
and T2.4 measurement record show deterministic five-sheet counts, save/load equality,
11.495--14.613 ms generation and all standard checks. Current generator/IO tests pass too.
