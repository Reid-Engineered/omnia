# P0.3 Spike PS1: SPICE extractor and `.olib` index timing

**Verdict: PS1 answered yes for the extractor; `.olib` index timing recorded on the Windows
development machine only.** A line-oriented extractor with no SPICE parser dependency extracts
every entry of the 20 spike decks as specified (24/24 extractions) and refuses every hostile
fixture with the expected error (15/15 in the campaign run; 16/16 after the review fixes of
pull request #133, which added `h16`). The grammar it needed beyond `parts-plan.md` `PD3`/`PK10` is

scheme; the unpacked-folder variant takes 60.4 ms there. **These Windows numbers certify
nothing (AGENTS rule 3).** The spike's Orion question is not answered here: `PB3` is certified
on Orion by `P3.1` (`HP1`), and [`P0.3/run.sh`](P0.3/run.sh) runs this spike's timing there in
one command if the owner wants an early number.

Ids: `PS1`; `PB3`; `PK2`, `PK3`, `PK7`, `PK10`; `PD2`, `PD3`, `PD4`, `PD9`, `PD10`. Defaults

## Extractor

### How it works

1. Decode each file as UTF-8 (refuse otherwise, `PD10`), drop a leading byte-order mark,
   CRLF → LF (`PD3`).
2. Screen every physical line of every file read, including unselected `.lib` sections, for the
   `PK10` directives (first token, ASCII case-insensitive, leading dot ignored).
3. Flatten `.include`/`.inc` and two-argument `.lib <file> <section>` that resolve inside the
   archive (`PK10` path rules: no `..`, no leading `/` or `\`, no drive or other `:`, no NUL;
   must exist; cycle and depth-16 checks). Every include path in a file is checked, including
   those in unselected `.lib` sections; only selected ones are followed (review fix, gap 14).
4. Join `+` continuations into logical lines; blank and `*` lines may sit between a line and its
   continuations. Inline comments (`;` anywhere; `$` and `//` after whitespace; quotes skipped)
   are cut for tokenising only.
5. Build a scoped definition table: `.subckt` (any depth), `.model`, `.param`, `.func`, and the
   `PARAMS:` names of each `.subckt` header as locals of that subcircuit. Duplicates in one
   scope and namespace, `.ends` name mismatches, unmatched `.ends` and unterminated `.subckt`
   are refused.
6. Extract an entry with its transitive top-level dependencies. Each reference resolves from its
   own scope outwards, so a local `.model` shadows a top-level one. Only the defining and
   element-name positions are skipped when collecting references (review fix, gap 13). Every `D`, `J`, `Z`, `M`,
   `Q` (slot 4, else 5) and `X` element must resolve to a model or subcircuit, or the extraction
   is refused.
7. Emit the physical lines of every block in flattened source order, byte for byte (comments,
   case, whitespace, interleaved comment lines kept).

### Grammar gaps for `P1.2`

Each was hit by a spike deck; the prototype handles all of them, and `P1.2` must too.

1. **Top-level `.param` and `.func` are dependencies.** `PD3` names only `.model`/`.subckt`
   closure, but decks 10, 16 and 18 reference top-level `.param`/`.func` from inside an entry.
   The closure must include them. Open point for the simulation lowering (not decided here):
   top-level `.param`/`.func` are global once lowered, so two embedded definitions that each
   carry `.param X` with different values collide in one netlist.
2. **Scoped resolution.** A model local to a nested `.subckt` may shadow a top-level model of the
   same name (deck 19). Treating "defined anywhere inside the block" as local drops the
   top-level dependency; resolve each reference from its own scope outwards.
3. **Missing references need a positional check.** Token matching cannot tell a missing model
   from a node name. Check the model slot of `D` (4th token), `J`/`Z` (5th), `M` (6th), `Q`
   (5th, else 6th: the substrate node is optional) and the subcircuit name of `X` (last token
   before `PARAMS:` or the first `k=v`). Models of `R`/`C`/`L` semiconductor forms and of
   switches `S`/`W` are still included when defined, but a missing one is not detected.
4. **`.lib <file> <section>`.** Section includes are common in corner libraries (deck 18).
   Flattening must select the named section (`.lib name` … `.endl`) and screen the whole file.
   The prototype refuses a one-argument `.lib` outside a section include, because dialects
   disagree on whether it starts a section or includes a whole file.
5. **Header and continuation handling.** Ports and `PARAMS:` can sit on continuation lines
   (decks 13, 20); `params:` may be lowercase (deck 15); some dialects omit `PARAMS:` and start
   parameters at the first `k=v`; spaces around `=` occur (deck 04). Port counts (`subckt_ports`)
   must come from the joined logical line after merging `a = b`.
6. **Comment rules.** `*` starts a comment line; `;` cuts anywhere; `$` and `//` cut only after
   whitespace (so `$` inside a token survives); quoted text is skipped. Blank and comment lines
   between continuations belong to the block and are kept byte for byte (`PD3`).
7. **Line endings.** Only LF and CRLF are normalised. A lone CR (old single-CR files) stays inside
   the line; `P1.2` should decide whether to refuse it or treat it as a line break.
8. **Non-UTF-8 decks.** Openly published decks often carry Latin-1 bytes in comments (`µ`, `°`).
   `PD10` refuses them (h05), which will refuse some user imports; the error should name the
   file and byte offset so users can convert the file.
9. **`PK10` over-refusal.** Matching `shell`/`system` as a first token also refuses a switch
   element named `SHELL`/`SYSTEM`. Kept: hostile by default.
10. **`PK10` is silent on netlist-wide cards.** `.end`, `.global`, `.option(s)`, `.temp` and
    analysis cards are not in `PK10`. Extraction only emits definition blocks, so library
    imports never carry them, but a hand-edited embedded deck could. Suggest `P1.2` raise
    whether `screen_embedded` should accept only `.subckt`/`.model`/`.param`/`.func` blocks at
    the top level (a `PK10` change, so the plan owner's call; not changed here).
11. **Namespaces and case.** Models, subcircuits, parameters and functions are separate
    namespaces; lookups are ASCII case-insensitive, output keeps the source case; duplicate
    names in one scope and namespace are refused.
12. **A useful property test.** `extract(extract(x)) == extract(x)` in embedded mode held on
    every deck and is a cheap `PINV9`-adjacent check for `P1.2`. It does **not** catch a dropped
    dependency (the re-extracted text simply lacks it too), so closure needs its own tests;
    see 13.
13. **Skip names by position, never by value** (found by the review of pull request #133). The
    first prototype removed every occurrence of an element's or definition's own name from the
    reference set, so `D1 a k D1` with a top-level `.model D1`, `XAMP i o XAMP` with a top-level
    `.subckt XAMP`, and `.model VT NMOS(VTO={VT})` with a top-level `.param VT` silently lost
    their dependency. Fixed: only the first token, the name a `.model`/`.subckt`/`.func` line
    defines (second token) and the left-hand side of each `.param name=value` are skipped.
    Four focused tests cover it (`same_name_*`, `param_right_hand_sides_are_references`; the
    three `same_name_*` tests fail on the first prototype). The re-check of the fix found that
    splitting `.param` tokens on their first `=` turned `GAIN={ LIMIT>=1 }` into an
    assignment to `LIMIT>` and dropped `LIMIT`. Assignments are now found only at nesting depth 0
    (outside `{}`, `()`, `[]` and quotes) and never in `==`, `!=`, `<=` or `>=`. This applies to
    `.param` lines and to `.subckt` header `PARAMS:` (tests
    `param_comparisons_are_references_not_assignments`, which fails on the previous fix, and
    `subckt_header_params_ignore_comparisons`). `P1.2` needs the same rule.
14. **Check every include path, selected or not** (found by the same review). The first
    prototype screened directive names over the whole file but skipped includes in unselected
    `.lib` sections before checking their paths, so `.include "../x.lib"` inside an unselected
    section was accepted. Fixed: every `.include`/`.inc`/`.lib <file> <section>` in a file read
    is checked under the `PK10` path rules (safe and inside the archive) and only selected ones
    are followed; hostile fixture `h16` and test
    `pk10_unsafe_include_in_unselected_section_is_refused` cover it.

After both fixes the 24 extractions are byte-identical to the committed campaign's
`results/extracted/` (compared file by file) and all 16 hostile fixtures are refused
([`results/runs/review-fix-extract/extract.json`](P0.3/results/runs/review-fix-extract/extract.json)).

### Archive notes for `P1.3`

- `zip` 9's `ZipArchive::by_index_data` gives central-directory sizes, names and symlink flags
  with no I/O, so every `PK3` check except the streamed one runs before any inflation. Each read
  is wrapped in `take(2 MiB + 1)`, so a lying header cannot make it read more than one entry's
  cap.
- The prototype checks the total and the ratio from declared sizes only. `P1.3` must also count
  inflated bytes against the 32 MiB total and the 100:1 ratio while streaming.
- `ZipArchive::new` parses the whole central directory before the 1,024-entry check can run;
  the 8 MiB file cap bounds that allocation. If `PK3` "before allocating" must cover the entry
  count too, `P1.3` needs to read the end-of-central-directory record first.
- The 8 MiB archive cap is checked only by `index_olib_file` (from file metadata). The
  seekable-reader entry point `index_olib` (used for the in-memory case) does not check it;
  `P1.3` must enforce it for every source, for example from the reader's length.
- The index's `parse_part` checks only part of `PK7`: parameter count, pin count, tag count and
  length, and description length. It does not check the 256-byte parameter-string cap or the
  2 MiB inline-SPICE cap (`PQ5`'s `spice` field). `P1.1`/`P1.3` must apply the full `PK7` set.

### Workload and schedule

- Pack: 500 parts (200 primitives, 150 `.model`, 150 `.subckt` with `[sim.supply]`),
  `manifest.toml`, `LICENSE` and 175 shared model decks: 677 entries, 473,185 bytes
  uncompressed, `.olib` 335,677 bytes Deflate, SHA-256
  `029884755ec3cf55161803e8a1b60e62f3d452651cc1d16ebc094fb39688d604`. Part files total
  410,565 bytes (≈ 820 bytes each, shaped like the `PD4` examples). ZIP entry order is a fixed
  shuffle, so the index sorts for itself.
- Index work per call: open, `PK3`/`PD2`/`PD10` checks over all 677 central-directory entries,
  read and parse `manifest.toml`, inflate and parse 500 `part.toml` files with
  `deny_unknown_fields`, `PK1`/`PK2` and partial `PK7` checks (see the `P1.3` notes), sort by
  qualified id, duplicate check. No model file is read and the index calls do no content
  hashing (`PD9`); the harness hashes the generated archive once, before timing, only to record
  its SHA-256 below.
- Cases: `olib-file` (from disk), `olib-memory` (same archive already in memory: parse and
  inflate cost only), `folder` (same pack unpacked).
- Schedule fixed in `run.ps1` before the first timed run: 10 repetitions, case order rotating
  each repetition ([order file](P0.3/results/index-windows-order.txt)), 20 untimed warm-up calls
  then 200 timed calls per case per repetition. Gate statistic: median of the run p99s, with
  their range. The OS file cache was warm (the pack was written just before).
- Binaries: SHA-256 in [`results/binaries-windows.sha256`](P0.3/results/binaries-windows.sha256).
  Provenance: the timed binaries were built from the working tree that became commit `8dd571a`
  with three differences, all made after the timed run: `index::parse_part` was private (made
  `pub` for the diagnostic breakdown), `src/bin/index_breakdown.rs` did not exist, and
  `conditions.ps1` printed raw process names. None of them is compiled into `extract` or
  `index_bench` beyond that one keyword. Rebuilding `8dd571a` with `pub` removed did **not**
  reproduce the recorded hashes (`7a67e683…`/`8dc726b8…` against `82c37ded…`/`22aa862d…`):
  release builds on this Windows machine are not byte-reproducible, so the provenance rests on
  the source, not on the hashes. The review fixes of pull request #133 changed `spice.rs` and
  `extract`; they leave `index.rs`, `pack.rs` and `index_bench.rs` unchanged, so the indexing

### Reading

- The `.olib` path is dominated by TOML parsing (about 13 µs per part) and inflation; the ZIP
  directory costs almost nothing. On this throttled machine its median run p99 sits at about
  40 % of the 50 ms `PB3` target.
- The folder path on Windows is dominated by per-file open cost (about 27 µs per open with
  real-time scanning on), and the first index after 677 files were written took 2.3 s. Its
  median run p99 (60.4 ms) is over the 50 ms target here. This is a non-reference number on
  battery under the quietest scheme and certifies nothing; `PB3` is judged on Orion. It is a
  risk for Windows, the first shipping platform, worth carrying into `P1.5`: options include
  caching a folder's index keyed by path, size and modification time, reading files in
  parallel off the UI thread, or steering large user libraries towards `.olib`. None of these
  is decided here.

## Verdict (`PS1`)

1. **Extractor: yes.** A lightweight line-oriented extractor handles continuations, nested
   subcircuits, inline comments, `PARAMS:`, local includes and transitive closure on all 20
   decks without a full SPICE parser, provided `P1.2` covers the fourteen points above (chiefly
   `.param`/`.func` closure, scoped resolution, positional reference checks and `.lib`
   sections).
2. **Index timing: recorded on Windows only.** 19.8 ms (`.olib`) and 60.4 ms (folder) median
   run p99 on the Windows development machine under poor conditions. The Orion number is not
   measured in this task; `P1.5` records non-reference timings with the real crate and `P3.1`
   certifies `PB3` on Orion (`HP1`). `bash docs/measurements/P0.3/run.sh orion` gives an early
   Orion number in one command if the owner wants it.
