## Investigation and implementation

A separate isolated copy of source 13b4809675c14b312636612d064f35d4b36ed96f was
instrumented with `Instant` around the first and second floods. One fixed 1,000-pair
diagnostic run measured respective phase means 1.214020 and 1.092444 ms (1,001 splits,
including setup). These are diagnostic phase costs, not acceptance statistics.
Both phases include point traversal, membership writes and fresh-vector growth;
there is no sampled CPU profile or claim of exact instruction-level attribution.
`perf` is unavailable. The reproducible instrumentation, baseline source and outputs
are retained in [diagnostics.tar.gz](T2.8-optimization/diagnostics.tar.gz).

Exploratory single 1,000-pair runs evaluated: two-ended search with the original
point table (remove p99 3.709018 ms); stable point slots with endpoint caches
(1.469594 ms); direct slot indices in component membership too (1.196121 ms);
and removal of per-point temporary neighbor/adjacency copies plus correct frontier
capacity retention (0.816153 ms). These were fixed diagnostic runs after distinct
code changes, not acceptance repetitions or discarded acceptance runs. Intermediate
source snapshots are not complete, so these are investigation notes, not isolated
causal estimates. The code changes and phase timings support reducing lookup,
copying and membership work together; they do not quantify allocations separately.

The final implementation stays within Connectivity, using existing dependencies:

- The coordinate hash map resolves stable internal slots in a Vec. Wire endpoints
  and component point lists cache those indices. Traversal and reciprocal membership
  repair use direct indexing. A slot can be reused only after its last wire end,
  label and pin leave. These internal slots do not change document IDs or NetIds.
- Removing a surviving-endpoint edge searches from both ends, alternating point
  expansions with separate visit stamps. A meeting proves an alternate path and
  leaves membership lists untouched. Otherwise the first exhausted frontier is a
  complete disconnected piece, which alone moves by swap-removal into a new component.
  The other component retains its vectors and membership. Frontier capacity survives
  either side winning. No tree, chain, coordinate-order or wire-direction assumption.
- Labels move by count; logical-net repair retains the existing single-label and
  multi-label rules. Pins remain attached to their point. NetIds remain valid only
  until the next edit. The independent from-scratch geometric/logical BFS oracle
  remains independent of incremental search and transfer.

This is a storage tradeoff: each wire now caches two usize slot indices and points
have a separate slot/free list. No rendering-memory/B9 claim is made. Cycle searches
can still traverse much of a component; this is not a general dynamic-connectivity
framework or a constant-time split promise.
