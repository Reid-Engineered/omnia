# T2.7 Orion milestone 2 gate

**Result: blocked on B3 and B4 present intervals.** The 2026-11-17 campaign completed all
120 invocations. Five present intervals in four motion runs exceeded their budget and did
not qualify for the compositor-idle exclusion in canvas plan section 2.1. Every other
budget check passed.

## Conditions

Orion ran Arch Linux (7.2.7-arch1-1), KDE Wayland, and Vulkan on the Core i5-7300U and HD
Graphics 620. Its native eDP-1 panel ran at 1920×1080 and 60.008 Hz, with 100% and 125%
scaling. AC stayed online and all four CPU governors reported `powersave` in every
snapshot. Power-profile and platform-profile values were unavailable. The campaign ran
from 21:50:44 to 22:20:45 EST in the active desktop session under `kde-inhibit`. The
runner restored the original 125% scale. The source was `d01488392fc3c27043318a0d1f10b23da1dfb074`.
The release binary's before and after SHA-256 fingerprints match.

## Results

- **B2 passed.** Median paired startup deltas were 5.862 ms at 100% and 4.688 ms at 125%,
  against the 300 ms limit.
- **B3 missed on one present interval.** All 1k frame-time medians of run p99s were in
  budget, ranging from 2.935 to 6.193 ms across cases. The 125% pan run 1 had a 25.007 ms
  interval against the 24.997 ms limit. The native frame signal arrived 12.943 ms after
  the previous present, which was within one refresh and failed clause (b).
- **B4 missed on four present intervals.** All 10k frame-time medians of run p99s were in
  budget, ranging from 3.925 to 8.991 ms across cases. Zoom at 100% recorded 42.480 ms
  (run 3) and 49.281 ms (run 10). Zoom at 125% recorded 46.340 ms and 53.376 ms (run 3).
  The limit was 41.661 ms. Each signal arrived within one refresh of the previous present.
  The four affected frames were near the bottom of the zoom sweep, at roughly 5.4% to
  8.2% camera zoom, and spent 22.258 to 29.380 ms in draw and 7.935 to 9.663 ms in
  present.
- **B5, B9 and B10 passed.** The worst frame work was 10.166 ms on 1k and 29.409 ms on
  10k. The 10k private-memory peak across reports was 114.840 MB and the maximum Omnia
  paint-path allocation count was zero in all 80 motion runs.

The tested renderer already applies the simplified far-zoom outcome named in T2.7:
merge collinear wire quads, omit the dense grid, and use symbol boxes below the K9
threshold. B4 still missed there. D4 requires the owner's decision before starting
Plan B. There was no rerun.

## Evidence and replay

The [summary](T2.7/orion-2026-11-17/summary.txt) gives all case medians and ranges and the
attribution for every motion run. The [run journal](T2.7/orion-2026-11-17/runs.jsonl)
contains the before and after conditions for each scheduled invocation. The
[archive](T2.7/orion-2026-11-17/raw-reports.tar.xz) contains all 120 original JSON
reports and their 120 logs. Its SHA-256 is
`08e629e72493a4397aaa040701daeab6a04a6117a78879d54af4f37a5cac5ef8`.
Replaying the archive on the Windows development machine reproduced Orion's summary
exactly and exited 1, the expected budget-miss status.

```sh
evidence=docs/measurements/T2.7/orion-2026-11-17
replay=$(mktemp -d)
cp "$evidence"/*.json "$evidence/runs.jsonl" "$replay/"
tar -xJf "$evidence/raw-reports.tar.xz" -C "$replay"
python3 -B docs/measurements/T2.7/gate.py summarize "$replay"
```

## Campaign command

The measurement used a clean checkout and the plain locked release bench. Run a fresh
campaign only when the gate is authorized for remeasurement and the source, binary, and
case order have been frozen.

```sh
cargo build --release --locked -p omnia-bench
kde-inhibit --power --screenSaver python3 -B docs/measurements/T2.7/gate.py run docs/measurements/T2.7/orion
```

The runner alternates the startup pair's order and rotates that pair with the motion
cases. B2 uses the median of paired deltas between ten-sample run medians. Motion runs
use 600 warmup and 600 measured frames. Exit 0 means the completed campaign passed,
1 means a budget missed, and 2 means the evidence was incomplete or conditions were
invalid.
