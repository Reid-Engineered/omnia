# U0.5 (Spike US4): `Doc::save` and `Doc::load` timing and file sizes

**Status:** `needs-human` — Windows 10-pass measurements and the frozen one-command Orion campaign are ready; the Orion reference run awaits the owner at the desk under [canvas-plan.md](../../canvas-plan.md) section 2.1.

## What is measured

Dedicated Criterion benchmark [crates/omnia-bench/benches/doc_io.rs](../../crates/omnia-bench/benches/doc_io.rs) over T2.4's deterministic stress-sheet generator (`generate(sheet, 42)`):

- **Cases (frozen):** `save_1k`, `load_1k`, `save_10k`, `load_10k`.
  - `1k` (`StressSheet::Parts1k`): `1,000` parts, `2,000` wires.
  - `10k` (`StressSheet::Parts10k`): `10,000` parts, `20,000` wires.
- **Operations:**
  - `save_*`: `Doc::save(&mut buf)` into a fresh `Vec<u8>` (UD7). Allocation and RON serialisation are inside the timed span; `assert_eq!(buf.len(), bytes_len)` and `drop(buf)` are outside.
  - `load_*`: `Doc::load(bytes.as_slice())` from in-memory bytes (RON v2). Parsing, validation, arena insertion, spatial-index build, and connectivity rebuild are inside the timed span; `drop(doc)` is outside.
  - Round-trip equality (`assert_eq!(Doc::load(bytes.as_slice()), doc)`) is verified in setup before timing.
- **Schedule:** 10 interleaved, rotating repetitions (`pass` 1..10, case order rotated by `pass - 1`), `100` individual `Instant::now()` observations per invocation (no warmup discarded; nearest-rank `p50` at index 49, `p99` at index 98, `max` at index 99), followed by Criterion (`sample_size = 20`, `warm_up_time = 1s`, `measurement_time = 4s`, `--noplot`).

Windows observation notes (diagnostic only):

- `load_10k` takes ~`50.7 ms` median (`53.0 ms` p99) even on the `i7-14650HX`, already above B5 (`50 ms`), confirming D8 / UD7's requirement to run `Doc::load` on the background executor.
- `save_10k` has a Windows median p99 of `15.082 ms`, with one noisy shared-session pass (`06-save_10k`) reaching `50.079 ms`. Because Orion (`i5-7300U`, 2 cores / 4 threads) has substantially lower single-thread throughput than the `i7-14650HX`, UI-thread serialisation on Orion could sit near or above `UB10`'s `33.3 ms` p99 limit.

### One-command Orion campaign

Prepared in [docs/measurements/U0.5/run.sh](U0.5/run.sh) and [docs/measurements/U0.5/summarize.py](U0.5/summarize.py):

1. If dependencies (`criterion`) are not yet cached on Orion, run once while online:
   ```sh
   cargo fetch --locked
   ```
2. On Orion, plug in AC power, close other user applications, and set the CPU scaling governor to `performance`:
   ```sh
   echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
   ```
3. Run the frozen campaign with one command from the repository root:
   ```sh
   bash docs/measurements/U0.5/run.sh
   ```
4. The script verifies tools, Linux, AC power, and `performance` governors before creating `docs/measurements/U0.5/attempt-XXXXXXXX/`, builds and hashes the `doc_io` release bench binary, executes the 10 rotating passes with before/after condition snapshots, archives `raw.tar.gz`, and writes `summary.txt`.
5. Record the Orion `p50`, `p99`, range, and `UB10` outcome (`< 33.3 ms` p99 for `save_10k`, or log the `DocSnapshot` request in the `doc` lane for `U0.6` if it misses) in this file.
