# U0.3 — Window chrome and goldens

US1 exercises native window gestures on a 1440 × 900 logical-pixel window with a 36 px
client-drawn bar. US5 asks whether Windows readback captures the bar and the deferred menu.
The spike uses the pinned GPUI APIs in UG5, UG12 and G12 and follows UD1's server-decoration
fallback on Linux. The Linux client border starts at 6 logical pixels, with no added shadow.

## Windows evidence, 2026-11-17

Development laptop, Windows 11 build 26200, Intel Core i7-14650HX, Intel UHD Graphics
(driver 32.0.101.7088). The primary display was at 1920 × 1200, 125% scale and 165 Hz.
Power was AC with the Silent power plan. These runs verify the prototype and readback.

- The [1800 × 1125 PNG](U0.3/chrome-menu.png) shows the Omnia title and File label on the
  bar, the three window controls, and the open File menu over the content below the bar.
  The menu's background and both entries are visible. US5 passed at 125%.
- The visible window opened at the requested size and exited at the one-second cutoff.
- The initial hidden readback hit a GPUI nested entity update. The final run captures via
  the window handle without leasing the root entity. Both capture logs are retained.
- The Windows backend reports `Server` for the decoration query, which describes the
  Linux negotiation path. Windows uses the transparent title bar and native hit-test areas.
- Native gestures remain pending UH1. No Linux or Orion observations have been recorded.

Raw logs: [first readback](U0.3/windows-readback.jsonl),
[final readback](U0.3/windows-readback-final.jsonl) and
[visible timeout](U0.3/windows-timeout.jsonl).

Reproduce the readback on Windows from the repository root:

```powershell
cargo run -p omnia-bench --features readback -- spike chrome --png u03-chrome-menu.png
```

## UH1 owner run

Run the same finite gesture session on Orion at the desk and on the Windows development
machine. Capture command output in a machine-specific file beside this report.

```sh
cargo run -p omnia-bench -- spike chrome --seconds 60
```

On each machine, try the blank title area drag and double-click, resize the edges and
corners, minimize and restore, maximize and restore, and close last. On Windows, hover
over maximize and try a snap layout. On Orion, record the granted decorations and whether
the 6 px resize border and unshadowed frame are usable. If server decorations are granted,
verify that the menu row stays visible and the compositor supplies the window controls.
Record what each gesture did. Wayland does not expose the window's screen position to the
spike, so a move request in the log needs visual confirmation.
