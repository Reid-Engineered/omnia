## Method and commands

Implemented in [shell_cache.rs](../../crates/omnia-bench/src/spike/shell_cache.rs):

- Over the `empty` sheet (`omnia_canvas::SheetCanvas`), the root view embeds a `.cached()` `PrototypeMenuBar` (nine UK2 labels, with its popover wrapped in `deferred(anchored()...occlude())`) and a `.cached()` status strip containing `PrototypeReadoutsView` fed by `CanvasEvent::Status`.
- `PrototypeReadoutsView::render` formats status text into a stack `FixedText<128>` buffer (`ours` scope) and returns a custom `Readout` element whose `paint` method draws cached single-character Source Code Pro `ShapedLine` glyphs inside one `window.paint_layer` via `window.paint_glyph`.
- Because GPUI's `Window::mark_view_dirty` (`gpui/src/window.rs:2522-2533`) walks `dispatch_tree.view_path_reversed(view_id)` and marks all ancestor views dirty, the spike supports both `--readout-layout nested` (literal UD18 wording: `PrototypeReadoutsView` nested inside `.cached()` `PrototypeStatusBar`) and `--readout-layout sibling` (`PrototypeStatusBar` static left slot and `PrototypeReadoutsView` placed as sibling `.cached()` views in the bottom row).

Commands run (after `60` warmup frames, measuring `300` hover frames across all 9 menu labels, occlusion/replay probes over `"View"`, and `600` `pan` frames at `1` device px/frame):

```powershell
cargo run --release --features scene-counts -p omnia-bench -- spike shell-cache --readout-layout nested --json docs/measurements/U0.4/shell-cache-nested.json
cargo run --release --features scene-counts -p omnia-bench -- spike shell-cache --readout-layout sibling --json docs/measurements/U0.4/shell-cache-sibling.json
```

Raw reports: [shell-cache-nested.json](U0.4/shell-cache-nested.json), [shell-cache-sibling.json](U0.4/shell-cache-sibling.json).

**US3 outcome and UD18 design note**:

1. Our readout formatting (`FixedText<128>`) and glyph-cache painting (`Readout::paint` with cached Source Code Pro `ShapedLine` glyphs) incur **0 allocations/frame of our code** across `subscribe`, `render`, `layout`, `prepaint`, and `paint` (and **0** `total` allocations in `subscribe`/`render`/`layout`/`prepaint`; `0` p99 `total` in `paint`). The UD18 shared-cell paint fallback is not required to eliminate render-path allocations.
2. However, nesting `ReadoutsView` *inside* a `.cached()` `StatusBar` view (`nested`) causes GPUI's `mark_view_dirty` ancestor walk to mark `StatusBar` dirty on every `CanvasEvent::Status` notify, yielding `status_bar_renders = 600`. Placing the static status-bar slots and `ReadoutsView` as **sibling** `.cached()` views in the workspace's bottom row (`sibling`) keeps `status_bar_renders = 0` and saves ~8 GPUI allocations (~6.1 KB) per frame.
