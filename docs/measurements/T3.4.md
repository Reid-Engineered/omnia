### Early diagnostic flags for Orion

1. **B10 holds everywhere**: `allocs_per_frame.ours.max == 0` on all 6 cases (`text`, `1k`, `10k` × `pan`, `zoom`), and all 3 `pan` cases sit at `1.59–2.22 ms` p99.
2. **`text-zoom` frame time risk (`25.854 ms` p99 / `35.226 ms` max on Windows)**: Continuous zoom across `K4` (`5%–3200%`) crosses `K11`'s `0.5 px` font buckets on nearly every frame, reshaping visible labels (`total` allocs p99 jumps from `16` on `pan` to `2,897` on `zoom`). Likely to challenge `B3` (`< 16.7 ms`) and `B5` (`<= 33.3 ms`) on Orion's i5-7300U.
3. **Zoom private memory risk (`B9 < 300 MB`)**: Every zoom sweep adds `~200 MB` of private memory over `pan` (`text-zoom` `313.44 MB`, `1k-zoom` `297.48 MB`, `10k-zoom` `373.71 MB` vs `10k-pan` `171.07 MB` and `T2.9`'s `94 MB` before text), consistent with GPUI's non-evicting glyph atlas accumulating textures across fine `0.5 px` buckets up to `128 px` during the full K4 sweep.

## Orion reference run instructions

From a clean checkout on Orion (AC power, `performance` governor on all 4 CPUs, other apps closed, native `eDP-1` 1920×1080 @ 60 Hz, local Wayland session):

```sh
cargo build --locked --release -p omnia-bench
kde-inhibit --power --screenSaver python3 docs/measurements/T3.4/gate.py run docs/measurements/T3.4/orion-$(date +%F)
```

Replay an archived campaign without re-running benchmarks:

```sh
python3 docs/measurements/T3.4/gate.py summarize docs/measurements/T3.4/orion-<date>
```
