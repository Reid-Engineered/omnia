## Gate procedure (owner decision 2026-11-17)

The owner decided on
2026-11-17 that a refresh the compositor skips while Omnia is idle does not count against
B3 (nor B4's interval rule), and chose to close T1.6 with a fresh untraced-Wayland gate run
whose misses are attributed automatically. The criterion is in canvas-plan.md section 2.1
and in [attribute.py](T1.6/attribute.py); [summarize.py](T1.6/summarize.py) applies it to
every present interval over 1.5 refreshes in every pan and zoom run, prints each one's
timeline and verdict, and passes B3 only with zero counted misses in every run. A run
without a usable trace fails. All other limits (frame p99, B1, B8, B10) are unchanged.
**In this gate, frame p99 (B3) and B10 are judged on the same pan and zoom runs, with the
bench trace on**; B1 and B8 runs are untraced.

The trace gives each draw's signal time and source (a native frame callback or a locally
scheduled request) and the main-thread work GPUI's foreground journal recorded, so the
classifier checks that the signal was a native callback (e) and that Omnia's main thread
was idle for more than one refresh before it (d), as well as (a) to (c).

What changed in [gate.sh](T1.6/gate.sh): pan and zoom `run`s set `OMNIA_BENCH_TRACE=1`
(start and idle do not; `WAYLAND_DEBUG` is never set). Schedule, cases, ten repetitions,
600 frames after 60 warm-up, order rotation and the automatic 100% then 125% scale switch
are as before. Results go to a new directory, `docs/measurements/T1.6/attributed/` by
default; the script refuses to start if it exists, so nothing recorded is overwritten. It
also records the source commit, `git status`, the binary's SHA-256 before and after, and
ends by writing `summary.txt` with summarize.py's verdict.

### Cost of the bench trace

By the code at the pinned GPUI revision: with tracing on, GPUI pushes one draw and one
present event per frame (an atomic load, a spin lock and a `VecDeque` push) and keeps task
timings it otherwise drops. Those calls run inside GPUI, outside every `ours` scope, so they
cannot count against B10; the occasional buffer growth lands in `total`, which Q5 reports
and never gates. The foreground journal that supplies signal sources and main-thread work
is recorded by GPUI in every bench build, traced or not, into a fixed ring; the bench only
reads it. Both are copied out once, after the last measured frame has been sampled, so no
per-frame work of ours is added. Evidence: the traced campaign of 2026-11-17 recorded `allocs ours` 0 in all
40 motion runs. Its frame p99s cannot isolate the trace's cost (different governor and
`WAYLAND_DEBUG` on). A Windows diagnostic, which certifies nothing
([trace-cost-windows](T1.6/trace-cost-windows/results.csv), i7-14650HX, Intel UHD
adapter at 165 Hz, Windows 11 26200, AC, source c4b821a, binary SHA-256 `69823d44…`, pan at
1536x864, five traced and five untraced runs in ABBA order) gave frame p99 median
**0.795 ms traced** [0.565, 1.255] against **0.848 ms untraced** [0.560, 0.973], `ours` 0
in all ten and the same total allocations per frame (8.0). Four of the ten runs lost window
focus (warning recorded), which drops present intervals but not frame times. The
difference is inside run-to-run noise. Those runs predate the journal read, which adds
work only at report time. A traced run with the final build on the same machine read the
journal with no entries lost, every measured draw's source native, and `ours` 0. Only the
Orion rerun's own numbers gate.
