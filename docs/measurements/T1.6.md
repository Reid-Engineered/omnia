## Protocol

[gate.sh](T1.6/gate.sh) runs four cases, ten repetitions each, interleaved, with the case
order rotating every pass, first at 100% and then at 125%. It was run from `/tmp` on Orion
so the checkout there stayed clean.

| Case | Command |
| --- | --- |
| B1 | `bench start --sheet empty --runs 10 --size <viewport>` (10 process starts per repetition) |
| B3 / B10 pan | `bench run --sheet empty --script pan --frames 600 --warmup 60 --size <viewport>` |
| B3 / B10 zoom | `bench run --sheet empty --script zoom --frames 600 --warmup 60 --size <viewport>` |
| B8 | `bench idle --sheet empty --seconds 10 --size <viewport>` |

[summarize.py](T1.6/summarize.py) validates every report and prints the tables below. It
checks for the HD 620 Mesa device (not software), full screen, scale, viewport, 60 Hz, no
warnings, 600 frames drawn, AC, DPMS, panel mode and scale, and rotation order. All
protocol checks pass. The script exits 1 because of the strict present-interval rows.

```sh
python3 docs/measurements/T1.6/summarize.py
```

### Bench changes made for this gate (lane `bench`)

Before this task, `--sheet empty` was still T0.1's plain paper rectangle and the bench
refused `--script zoom` ("T2.6"). So the bench could not measure the milestone-1 sheet.

- `--sheet empty` now paints `omnia-canvas`'s `SheetView`: the T1.4 paper and the K10
  nested, fading dot grid, in the Graphite theme. It goes through
  `SheetView::paint_quads`, which is the whole body of `SheetView`'s paint with the GPUI
  call left to a sink, so our allocations are counted apart from GPUI's (Q5). The camera
  is an `omnia_canvas::Camera` centred on the origin. T0.1's window remains available as
  `--sheet t01`, and the spike scripts' baseline now names it.
- `--script zoom` zooms about the viewport centre across all of K4, geometrically and at a
  constant speed: 100% → 3200% → 5% → 100% every 600 frames (about 0.031 octaves per
  frame). So every grid level and every fade is drawn. `zoom` needs `--sheet empty`.
- `idle` takes `--sheet` (default `empty`), so B8 idles the real sheet.
- After the owner's B3/B4 decision, `bench run` reports `missed_refreshes` (present
  intervals longer than 1.5 refresh intervals), `present_intervals_over_2_5_refreshes` (B4)
  and `max_present_interval_ms`. GPUI's own count, refreshes that a frame's *work* overran,
  was reported as `missed_refreshes` before; it is now `work_missed_refreshes`. The counts
  come from GPUI's present-interval histogram. At its three significant figures they can
  over-count only values within 0.1% of the limit, and never miss one.

The reports in `T1.6/s100` and `T1.6/s125` were made before that change. In them,
`missed_refreshes` is GPUI's work-based count (0 in every run). They hold only per-run
summaries of the present interval (mean, p50, p95, p99, max), not per-frame timestamps or
the histogram. So the new count is exact (0) only for runs whose max interval is at most
1.5 refreshes; for a run above that, the reports show only "at least one".
`summarize.py` judges both kinds of report.

The bench path does not include T1.5's input handling or the status bar. The scripts set
the camera directly, as plan section 2 defines `bench run`.

The one miss is 100% pan, run 7 (`s100/pan-7.json`):

- Its longest interval is 30.87 ms, about two refreshes.
- Its p99 interval is 19.33 ms, so at most 1% of its ~600 intervals (6) are over the limit.
  Its mean interval, 16.716 ms against about 16.697 ms in the other runs, fits exactly one
  miss.
- The frame was not the cause. That run's frame work peaked at 9.38 ms (p99 4.71 ms), and
  GPUI counted 0 late frames. The slot was lost after submission, to the compositor or
  another process. Other apps were running at the time (see below).

The plan says "zero missed refreshes" but not how ten runs combine. This summary applies it
to every run, as B10 is applied, rather than taking a median of counts. Under that reading
the SSH campaign does not pass B3 for pan at 100%; under a median-of-runs reading it would.
The rerun with other apps closed decides it on clean data. If a miss recurs there, the
owner decides how runs combine.

The old wording, "median present interval ≤ one refresh", measured 16.679 to 16.695 ms
against 16.664 ms: 14 to 31 µs over, through timestamp jitter. That is why the owner
replaced it.
