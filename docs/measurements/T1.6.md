## Protocol

[gate.sh](T1.6/gate.sh) runs four cases, ten repetitions each, interleaved, with the case
order rotating every pass, first at 100% and then at 125%. It was run from `/tmp` on Orion
so the checkout there stayed clean.

| Case | Command |
| --- | --- |
| B1 | `bench start --sheet empty --runs 10 --size <viewport>` (10 process starts per repetition) |
| B3 / B10 pan | `bench run --sheet empty --script pan --frames 600 --warmup 60 --size <viewport>` |
| B3 / B10 zoom | `bench run --sheet empty --script zoom --frames 600 --warmup 60 --size <viewport>` |
| B8 | `bench idle --sheet empty --seconds 10 --size <viewport>` |

[summarize.py](T1.6/summarize.py) validates every report and prints the tables below. It
checks for the HD 620 Mesa device (not software), full screen, scale, viewport, 60 Hz, no
warnings, 600 frames drawn, AC, DPMS, panel mode and scale, and rotation order. All
protocol checks pass. The script exits 1 because of the strict present-interval rows.

```sh
python3 docs/measurements/T1.6/summarize.py
```

### Bench changes made for this gate (lane `bench`)

Before this task, `--sheet empty` was still T0.1's plain paper rectangle and the bench
refused `--script zoom` ("T2.6"). So the bench could not measure the milestone-1 sheet.

- `--sheet empty` now paints `omnia-canvas`'s `SheetView`: the T1.4 paper and the K10
  nested, fading dot grid, in the Graphite theme. It goes through
  `SheetView::paint_quads`, which is the whole body of `SheetView`'s paint with the GPUI
  call left to a sink, so our allocations are counted apart from GPUI's (Q5). The camera
  is an `omnia_canvas::Camera` centred on the origin. T0.1's window remains available as
  `--sheet t01`, and the spike scripts' baseline now names it.
- `--script zoom` zooms about the viewport centre across all of K4, geometrically and at a
  constant speed: 100% → 3200% → 5% → 100% every 600 frames (about 0.031 octaves per
  frame). So every grid level and every fade is drawn. `zoom` needs `--sheet empty`.
- `idle` takes `--sheet` (default `empty`), so B8 idles the real sheet.

The bench path does not include T1.5's input handling or the status bar. The scripts set
the camera directly, as plan section 2 defines `bench run`.

The roadmap's T1.6 row for B3 asks only for "p99 < 16.7 ms". That passes with about 4x
headroom. Plan section 2 adds "and median present interval ≤ one refresh". At both scales
that median is 14 to 31 µs (0.1 to 0.2%) above 1/60.008 Hz.

The evidence says no frames were dropped:

- 0 late frames and 0 missed refreshes in all 40 runs.
- Each run drew 660 frames in 11.08 to 11.10 s of wall time, which is 60.0 fps including
  start-up.
- The present-interval p99 was 18.3 to 19.4 ms, far below two refreshes.

Present intervals are CPU-side timestamps around the Vulkan present (G13). They scatter
around the refresh period, so their median can land on either side of it. The script does
not round this away. Whether "≤ one refresh" means exactly the panel's vsync interval, or
allows for timestamp jitter, is the owner's decision, not this task's (rule 3).
