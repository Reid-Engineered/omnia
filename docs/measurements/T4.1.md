# T4.1 connectivity: measurements

**Not the reference machine.** Q4 names the Orion laptop (plan section 2.1) as the only
machine that can mark a budget met. T4.1's Done-when check requires one wire add and one
wire remove under 1 ms on `10k`; these numbers are recorded on the Windows development
machine.

## Hardware and setup

| | |
| --- | --- |
| Machine | ASUS TUF Gaming F16 FX608JMR, ASUS "Silent" power scheme; `Win32_Battery.BatteryStatus` read 1 (on battery) |
| CPU | Intel Core i7-14650HX, 16 cores (8P + 8E), 24 threads |
| Memory | 32 GB |
| GPU, display | Not used: CPU-only (`omnia-doc`, no GPUI). Host GPUs: NVIDIA GeForce RTX 5060 Laptop GPU + Intel UHD Graphics; 1920x1200 at 125%, 60 Hz. |
| OS, toolchain | Windows 11 10.0.26200, Rust 1.98.1 (`rustc 1.98.1`), `bench` profile (release), criterion 0.8.2 |
| Command | `cargo bench -p omnia-doc --bench connectivity` |

## The sheet

T2.4's stress-sheet generator (`crates/omnia-bench/src/generate.rs`) has not landed on
`origin/main` yet, so `crates/omnia-doc/benches/connectivity.rs` builds an equivalent seeded
synthetic sheet: **10,000 parts and 20,000 wires** (the `10k` counts in plan section 2),
plus net labels (`GND`, `VCC`, `CLK`) on ~10% of parts.

- Parts on a 100 x 100 lattice, 7 grid steps apart.
- Horizontal wires chain groups of 8 parts into multi-wire components; vertical wires are
  short stubs with 2% long buses spanning 20 to 60 rows.
- Two extra 100-wire chains are included in the stress case to measure bridging and splitting
  a 200-wire connected component.
- Once T2.4 lands, `benches/connectivity.rs` should switch to T2.4's `10k` generator.

## Results

Times are criterion's `[low, estimate, high]` for a single operation on the `10k` sheet:

| Case | Time | Notes |
| --- | --- | --- |
| `wire_add_leaf_10k` | [85.60, **93.94**, 103.50] ns | Add one dangling wire to an existing component |
| `wire_remove_leaf_10k` | [53.45, **54.17**, 54.99] ns | Remove one dangling wire (O(1) leaf fast path) |
| `wire_add_bridge_10k` | [278.5, **284.0**, 290.0] ns | Union two ~8-wire components |
| `wire_remove_split_10k` | [996.8 ns, **1.035 µs**, 1.077 µs] | Remove bridge wire and BFS-reflood both components |
| `wire_add_and_remove_pair_10k` | [1.054, **1.068**, 1.081] µs | Round-trip add + remove of a bridge wire |
| `wire_add_200wire_bridge_10k` | [664.3, **676.1**, 689.2] ns | Union two 100-wire chains |
| `wire_remove_200wire_split_10k` | [6.990, **7.088**, 7.195] µs | Remove bridge wire and BFS-reflood 200-wire component |
| `rebuild_10k` | [8.022, **8.436**, 8.892] ms | From-scratch rebuild over all 20,000 wires + labels |

Every incremental wire add and wire remove is under **7.2 µs** (< 0.008 ms), more than
130× below the 1 ms target.
