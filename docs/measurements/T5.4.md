## Aborted Orion campaign on 2026-11-25 (`incomplete`)

- **Provenance:** Clean `origin/main` at `343a3312ce8f01cb0e88142c091b9f700274f419`, started remotely with owner approval via `owner-run.sh --remote` (`21:37:26Z–21:39:40Z`, `omnia-t54-owner.service`; AC online, lid open, DPMS on, screen unlocked, all four CPUs on `performance` governor and restored to `powersave` on exit, `kde-inhibit` active, Baloo idle).
- **Outcome:** `incomplete` (gate exit `2`). Only `s100/start-empty-1` and `s100/start-1k-1` ran; the third invocation (`s100/1k-drag-part-1`) exited `3` with `bench: drag-part left lifted Dragging state before measured frames began` before any timed motion frames were collected.
- **Root cause:** On Wayland (`OMNIA_BENCH_FULLSCREEN=1`), `DragPhase::Press` dispatched `MouseDown` before KWin finished `xdg_toplevel::configure` and delivered `wl_pointer::Event::Enter`. GPUI's Wayland client (`gpui_linux/src/linux/wayland/client.rs:2408-2415`) calls `window.set_hovered(true)` and synthesizes `PlatformInput::MouseMove(MouseMoveEvent { pressed_button: None, .. })` on `Enter`, which arrived right after the first fullscreen present and cancelled the in-progress drag during warm-up (`OverlayView::on_mouse_move` -> `LostCapture`). In windowed mode on Orion, late `xdg_toplevel::configure` arriving during `Press` also caused `press_sheet_paints = 1`.
- **Harness fix (for next campaign):** `crates/omnia-bench/src/drag_part.rs` now runs `DragPhase::Settle` before `Press`: when `harness::fullscreen_requested()` is true (Linux `OMNIA_BENCH_FULLSCREEN`), it waits for both `window.is_fullscreen()` and `window.is_window_hovered()` (up to `60` frames, failing fast if unmet) and then draws `8` post-ready settle frames before `MouseDown`. Non-fullscreen runs draw `8` best-effort settle frames. `frames.startup_draws` records the measured pre-warmup draw count so `docs/measurements/T1.6/attribute.py` stays exact. The next Orion campaign will run on the rebuilt release binary from `origin/main` with this fix.
